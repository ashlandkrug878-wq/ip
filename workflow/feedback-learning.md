# 淘汰备注 → 可追溯避错经验

用户2026-10-28授权：历史每日IP全部入库供筛选，淘汰原因逐步积累总结，后续创作避免重复错误。

## 每轮执行

1. 读取最新 data/reviews/ 原话、关联方案和图，运行 scripts/build_feedback.py；保留用户原话，不覆盖、不润色。
2. 分清：原点不喜欢、表达空泛、造型不喜欢、生成偏离、记忆点弱、同质化、工艺过繁、配色不喜欢。只归类明确内容，不能用AI自己的预评当用户证据。
3. 单条原因仅约束对应候选；2个独立IP的同类原因记为“观察中”；至少3个独立IP、跨至少2个批次反复出现的明确同类原因，才写为“持续避错建议”。这是工作阈值，不是统计学用户验证。
4. 写 data/feedback/learned-rules.json，每条包含 id、category、summary、scope、state、evidence（原话、IP id、batch、review路径）、counterexamples、first_seen、last_seen。新版本追加 history，不抹掉旧判断。相反的保留和批注作为反例，新且更具体的用户指示优先，冲突时降为观察中。
5. 特别区分“这个原点可以，但具象化太差”与“不要这个原点”；前者只约束造型转译，不能把原点加入黑名单。没备注的淘汰不参与原因总结，只避免重复该具体候选。
6. 创作前把适用规则变成检查清单；创作后列出遵循了哪条、改了什么。不得一概排除某物种、性别、风格或材料，除非用户明确要求。
7. 每轮交付用1—3句说明新增/更新经验及证据量；没有新证据就不虚构新结论。只根据用户筛选学习，不能自动替用户淘汰新方案。

## 存储边界

淘汰是软归档，保留 data/ips、images、data/reviews；前台默认隐藏，“淘汰档案”可恢复。公开仓库的所有批注与总结可公开访问，不是私密后台。
